# work as a research gym

Start with one question and one observable outcome. Keep this repository small enough that the user can understand every experiment record. Favor a playable example or a short video followed by a prediction and a small test.

## first session

1. Build the wiki and open `docs/start/first-baseline/index.html`.
2. Ask the learner to predict one baseline failure mode and explain why.
3. Copy `templates/hypothesis.md` into the baseline experiment only after the learner has stated a hypothesis.
4. Resolve baseline and rival identities from current upstream sources. Review the compute estimate together.
5. Freeze the evaluation protocol before a separately authorized run.

This scaffold has not run a baseline or trained a model. Documentation examples are plans, not executed receipts.

## keep reasoning attributable

Preserve the user's own prose. Offer edits as suggestions when they alter meaning. Record who made a prediction and when. An agent can organize evidence, find a counterexample, or explain a diagnostic; the learner supplies the interpretation when that is the exercise.

Use explicit labels in records: hypothesis, planned method, observation, interpretation, uncertainty, decision. Link a finding to its protocol version, exact artifacts, and analysis command. Leave unknown fields unknown.

## research rhythm

Predict, lock, run within budget, inspect, and decide. Record a negative result with the same care as a positive result. Choose the next experiment from the evidence, not from a desired leaderboard story. A report must explain what the evaluation cannot establish.

Native GitHub Wiki and generated HTML are publication formats. Edit the canonical articles in `wiki/src/`. Read `AGENTS.md` for operational limits and evidence requirements.
